# 使用反馈与 Gitee Issue

## 何时报告

用户随时可以指出异常。先弄清他要的结果，区别创作偏好、单次生成波动、使用环境与技能本身。单次就能定位的缺陷也值得报，例如安装包引用了缺失文件、更新器在支持的环境下报错、两条技能规则相互冲突，或用一个简单例子就能看出正文遗漏了指定角色。功能缺口有明确使用场景和预期结果，也可以提。能在本轮改好的先改，仍会影响后续使用的通用缺陷可同时上报。仅改表演口味、仅遇到一次随机偏差或本机暂时断网，按原任务处理。关于生成效果，沿用[成片偏差的判断](prompt-revision.md#先判断偏差来自哪里)。

## 怎样提交

1. **写最小报告。** 标题说明“什么情况下出现什么问题”。正文写技能版本（安装目录的 `.gitee-revision`，能取到时用短提交号）、简短复现步骤、预期和实际结果。按需要附宿主名称或脱敏后的报错。用甲乙等虚构角色和新写的短句代替用户材料。省去原剧本、对白、客户或项目名、媒体、私有链接、对话记录、本机个人路径和凭据。用户明确不愿反馈时就到此为止。
2. **到指定仓库查重。** 目标是 Gitee 的 `a1meon_admin/seedance25_prompt`。检索同义标题，并检查相关的未关闭和已关闭 Issue。已有同一问题就复用链接。有证据表明已修的问题在新版本复发时，说明版本和新增证据，并关联旧 Issue。
3. **按使用者的授权提交。** “有必要就向这个仓库提 Issue”、本次明确要求上报，或已有对该仓库的持续授权，都可直接执行。仅安装或提出问题的使用者若尚未授权，用独立消息展示脱敏标题和摘要，一次确认是否发布。成功以仓库返回的 Issue 编号或可打开的详情页为准。发布超时或响应不明时，先查 Issue 列表确认是否已创建，再决定下一步。
4. **选择可用入口。** 优先用已连接的 Gitee 工具 `list_repo_issues` 和 `create_issue`，或在[仓库 Issues](https://gitee.com/a1meon_admin/seedance25_prompt/issues)中查询和新建。只有终端时，从安装目录执行下列命令；创建需要已通过宿主环境配置的 `GITEE_ACCESS_TOKEN`。正文文件使用 UTF-8，只放已脱敏的内容。无需在对话中索取令牌。

    ```sh
    python3 scripts/report_issue.py list
    python3 scripts/report_issue.py create --title "简明的问题标题" --body-file /path/to/issue.md
    ```

反馈任务单独返回 Issue 链接。若还要交付视频提示词，用独立状态消息报告链接或阻塞原因；提示词正文保持既定格式。无法登录、缺少权限或仓库未启用 Issues 时，保留脱敏草稿并如实说明。如本轮还能完成提示词任务，继续交付。
