# Seedance 2.5 提交格式

## 纯文字生成

无对白的简单事件用自然段；有台词时先列【参考素材职责】，为每名发声者逐行登记音色，再写事件。先写主体和主要动作/事件，融入场景，再按需要写光色、景别与镜头变化、声音。复杂叙事先用一句概述交代谁在何处经历什么，再用「镜头一」「镜头二」或阶段写具体情节，贯穿性的要求放在固定收尾行之前。单镜可以把机位紧贴动作写，避免表演和摄影变成两份彼此矛盾的说明。

写概述也要尊重揭示时机和镜内边界。若概述会点出仅在画外或尚未揭示的人物道具，直接从第一镜开始。仅作音色的素材就在职责行绑定，不因列入参考而让人物入画。「她看着某人做某事」仍可能把某人画出来；镜头只给听者时，换成她的视线方向、脸上的反应及必要的画外声音。

单一状态也可以独立成镜，镜头句例如「固定面部近景，她有些失望，目光慢慢垂下。」已有事件或转折时可用下面的骨架，按需要取句。

    [人物]在[场景]中[完成事件，抵达结果]。
    镜头一，[景别、可见主体与相对位置]。[主要事件；若人物关系在此刻改变，把走位和表演写进同一句动作]。
    镜头二，[新取景中可见的承接状态]。[本镜的反应或转折，如有]。
    [本场需要的光线或声音，可在相应镜头内写完]。
    无bgm，无字幕

一镜到底写成一个连续段落，可以有若干动作阶段。用户提供的镜号照录。用户已给时间段或要按秒控制时，沿用或分配连续不重叠的时间预算，保住原故事节奏。仅给总时长时，根据它决定可容纳的台词和转折，正文用镜头或阶段。已有长台词先留足讲话和必要停顿的时间。允许设计分镜时可以跨镜接话；已锁分镜时先精简陪衬动作。时间紧时保留指定的原句和镜头，优先压缩陪衬。画幅、分辨率、帧率、总时长、音频开关留在生成设置。

## 有素材

有多主体、多镜或多种素材时，用以下段名说明职责和先后。简单单镜写成一段自然语言。

    【生成目标】
    一句话写事件。
    【参考素材职责】
    @图片1为林岚的外貌参考。
    @视频1为运镜参考。
    @音频1为林岚的音色参考。
    【主体与关系】
    写清多人身份、站位、共用道具的出入手。
    【事件脚本】
    每镜按事件顺序写各个有戏的入画角色，谁在看哪里、带着什么情绪、怎样行动或保持原态；把这些放在同一段动作里。结尾交代需要承接的状态。
    【保持一致】
    只写这场戏确实需要跨镜继承的条件。
    无bgm，无字幕

按本段替换示例映射，沿用用户实际标签与编号。每行只写素材和参考用途，到“参考。”结束。剧本文件、文件名、未采用素材、上传状态和使用解释均省去。即使只有剧本附件，仍可从中提取台词，并按[音色编号规则](performance-workflow.md)为发声者预留音色。具体镜号、画内外、走位、参考动作何时发生等写在事件脚本中。没有可列的映射时直接写镜头。

## 原片、分镜与边界状态

| 用户意图 | 怎么写正文 |
|---|---|
| 改已有片段的表演 | 指定唯一母版，写人、位置、原动作→目标动作、作用区间、须继承的口型/对白/镜头/背景与结束姿态。仅改声音时只指定声音对象与范围。 |
| 用视频为新画幅或新时长重新生成 | 将源片列为内容和时序参考，重新描述新构图里的可见事件。在生成目标中直接写要重新生成的画幅、时长或内容。 |
| 向后或向前延长 | 指定唯一源片和方向。后延从尾部的视线、手势、站位、声音继续；前延设计动作，使新片尾自然抵达原片开头。改原片且还需延长时，先编辑，第二条提示词承接新母版。 |
| 首帧、首尾帧或多关键帧 | 逐帧说明是哪一张、可见状态和如何过渡。平台首帧/尾帧模式使用对应角色参数；普通参考图的文字指代是构图参考。区分硬边界与中间可发挥的表演。 |
| 宫格分镜、白模 | 写明逐格阅读方向和情节顺序，宫格边框与标注只用于解读。白模参考按指定维度继承走位、时序和机位，再补演员表情。不要让参考图中的文字或预演外观变成成片内容。 |

## 声音、台词、文字

对白用 `{原台词}`，环境声或动作音可用 `<音效描述>`。场景中原有的标牌、信件等可读文字按剧情保留。清理与段尾约束冲突的背景配乐和叠加字幕指令，保留原对白与现场声。每段最后一行固定为 `无bgm，无字幕`，包括无对白镜头、续写和视频编辑。

先交代谁在画内或画外、怎么说，再放台词一次。例如「画面左侧的乔宁先等对方坐下，才用英语轻声说 {Sit here.}」。逐句绑定说话人，明确对手闭口时在做什么。用户已指定语言、口音或音色参考就逐人继承；给了英文句子可标英语，无需推定地区口音。用户给定的原词、标点、说话人及语言逐字保留，把吞音、气口、语尾、重音写在括号外。只给说话意图时用表演表达，除非用户要求创作台词。要无对白时可以保留指定的呼吸和现场音；要静音时也省掉这些声音。

## 核对写法与预期效果

先用[偏差判断](prompt-revision.md#先判断偏差来自哪里)核对问题是否来自本稿。确定要改时，只改相关部分。

- 原稿用“眼里冒出蓝火”比喻压怒，用户要的是写实表演，就换成怒意与自然眼神。单次生出非预期特效、原稿却没有相关暗示时，保留原句。
- 原稿把台词同时写进对白和字幕栏时，保留对白，删去叠加字幕指令。
- 反应提前，先看原句有无把疑惑写成全镜起始状态。若用户明确要某个称呼之后才起疑，把变化放回那个称呼。时间顺序已经准确时继续沿用。
- 两人站位或说话者在相邻镜头被写反，只修出错的主语、方向或接点。镜头内容过密，先精简重复动作；只在用户未提供分镜或明确授权时考虑拆镜。
